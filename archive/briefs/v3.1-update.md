# A Matter of Time — v3.1 update

Apply this to the existing v3 build. **Where this file and `CLAUDE.md` disagree, this file wins.** When you're done, rewrite `CLAUDE.md` to describe v3.1.

v3.1 is about getting the content and the feel right before scaling up. The biggest change: **all text now lives in one human-editable file, `content/story.md`**, which the game reads directly.

## 1. `content/story.md` is the single source of truth

Put the attached `story.md` at `content/story.md`. It contains every word players see: UI strings, the disclaimer, the Intro, the history Timeline, the six Values, all Scenarios, Events and Futures, image descriptions, the image style guide, and the tunable settings.

**Delete all hard-coded content** from `data.js` (or wherever it currently lives): scenarios, futures, values, intro lines, timeline events, UI strings. The engine should hold only logic.

### How the game reads it

- At startup, `fetch('content/story.md')`, parse it, validate it, then start. **Edits to the file show up on the next page load**, with no build step.
- `fetch` doesn't work when a page is opened directly from Finder (`file://`). So:
  - Add **`start.command`** at the project root, a double-clickable macOS script (run `chmod +x start.command`) that `cd`s to its own folder, starts `python3 -m http.server 8000`, and opens `http://localhost:8000` in the default browser.
  - If the fetch fails, show a plain, friendly screen: "To play, double-click start.command in the game folder." Don't just leave a blank page.
- Put the parser in **`js/story-parser.js`**, written so the browser and Node (`tools/`) can both import it. Write it once and use it in both places.

### File format (the parser must follow these rules exactly)

- `# SECTION` lines start sections: `SCALE`, `SETTINGS`, `UI TEXT`, `INTRO`, `HISTORY TIMELINE`, `VALUES`, `IMAGE STYLE GUIDE`, `ROUND 1`…`ROUND 4`, `EVENTS`, `FUTURES`. Ignore unknown sections, such as the how-to-edit notes at the top.
- `## id` starts an item (a Value, Scenario, Event or Future). The id is the whole heading text.
- `### Choice A/B/C` starts a choice inside a Scenario. `### Story N` starts a story inside a Future, and everything under it until the next heading is the story text.
- `**Label:** value` sets a field. A field continues onto the following lines until the next `**Label:**`, heading, or `---`. **Multi-paragraph fields** (`Story`, `As a result`, story text) split into paragraphs on blank lines.
- **Effects:** `power +1, control -2`. Valid names are only `power`, `control`, `handover`, `unity`, `reality`, `equality`.
- **Next:** list lines `- target-id | lead-in sentence`.
- **Targets** for Futures use the same syntax as Effects. Text in brackets means no targets (used by `long_middle`).
- History lines: `- Date | Title | Line | URL`.
- In INTRO, `**Lines:**` holds the lines; blank lines mean a pause; `[MONTAGE]` marks the montage; ` / ` splits a line shown as two stacked lines; `*word*` is italic. `**Montage:**` is a comma-separated list.
- `**Image:**` is empty for now. Later it will hold a path like `assets/cards/generated/r1-lab.png`. When it's empty, use the placeholder card front.

### Validation (in the browser console, and in the check tool)

Report clearly, with the item id, when:
- a Next id doesn't exist, or points to the wrong round. A Choice in round N must link to round N+1. An Event with `After round: N` must link to round N+1.
- a Scenario doesn't have exactly 3 choices
- a Round 1–3 choice doesn't have at least 1 Next entry
- an Effects line has an unknown Value name
- a Future has no stories
- a required field (Headline, Date, Place, Story, Question, Text, Effects, As a result) is missing

In the browser, still run the game if possible, skipping broken links and logging warnings.

### `tools/check-story.js` (run with `node tools/check-story.js`)

1. Parse and validate `content/story.md`, and print any problems.
2. **Update the SCALE table in place** in `story.md` (only the numbers in that table): scenarios per round, events, the total, Futures, Future stories, and distinct paths through the game (count every combination of starting card, choice, possible event and possible next card).
3. Run the balance simulation (30,000 random games plus the best-play reach check for each Future) and print: the share of each Future, the best-play reach per Future, how often each card appears, and any card that never appears.

Remove the old `tools/simulate.js`; `check-story.js` replaces it.

## 2. Flow order (changed)

1. **Intro** (lines from story.md, as before).
2. **Disclaimer** screen (text from `UI TEXT → Disclaimer`), with the **Begin** button below it. This click also starts the audio.
3. **Timeline:**
   - It plays by itself. The history Timeline scrolls automatically from the oldest event down to **Now** over about 12–15 s, easing in and out. The **Now** marker reads "Now · 2026".
   - The player can scroll back at any time. Manual scrolling pauses the auto-scroll, and a small "Return to Now ↓" button appears. Clicking it, or scrolling back to Now, resumes.
   - When Now is reached, hold for about 2.5 s, then the deck appears and the first card is drawn.
4. **Rounds.**
5. **Future reveal.**
6. **See what you chose.**

"Play again" skips the Intro and Disclaimer and starts at the Timeline (still skippable).

**The present year is 2026.** Anywhere the UI refers to "now" or "today", it means 2026.

## 3. Rounds, links and Events

### Picking cards

- **Round 1:** a random card from the 5 in `# ROUND 1`.
- **Round 2:** pick randomly, 50/50, between the two cards in the chosen Choice's Next list. (The v3 "coverage" rule is removed. It kept picking the same cards.)
- **Rounds 3 and 4:** rank the two Next cards by the same scores as v3 (explore for round 3, tiebreaker for round 4). Pick the higher-ranked one with probability `Best-fit pick chance` from SETTINGS (0.6), otherwise the other.
- A card never appears twice in one game. If both Next cards were somehow already used, pick any unused card from the next round.
- Read `Long Middle threshold`, `Event chance` and `Best-fit pick chance` from SETTINGS rather than hard-coding them.

### Lead-ins (cohesion between cards)

Every Next entry carries a lead-in sentence. After "As a result…" and the card flying to the timeline, the interstitial now shows two lines:

1. the time gap ("Two years later." / "That same year." / "Years pass.", computed from the two dates as in v3), then
2. beneath it, in the body font, the **lead-in sentence for the card that was actually picked**.

Hold for about 3 s (longer than v3, since there's now a sentence to read), or until the player clicks. Then draw the next card.

### Events (new)

Events are things that happen to the world that the player can't control, like an earthquake, a market crash or a collapsed treaty. They make the game feel like a choose-your-own-adventure grounded in a world that doesn't wait for you.

- After the player's Round 2 choice, and again after their Round 3 choice, roll `Event chance` (0.35).
- On a hit, choose an Event whose `After round` matches the round just played. Prefer Events whose Next list shares a card with the player's Choice's Next list; if none do, choose any eligible Event at random. Each Event appears at most once per game.
- **Show the Event as a card**, drawn and flipped like a Scenario card but visibly different: a small label above the headline reading `UI TEXT → Event label` ("Out of your hands"), and no Choices, just the story and a **Continue** button. Use the same placeholder front for now.
- Apply the Event's Effects to the hidden Values.
- **The next Scenario is then picked from the Event's Next list**, not the Choice's, using the normal rule for that round. The lead-in shown is the Event's lead-in for that card.
- On the timeline strip and in "See what you chose", Events appear as their own entries (date and headline, with the "Out of your hands" tag), styled more quietly than the player's choices: no accent colour, and a dashed connector.

## 4. Futures: multiple stories

- Each Future has several `### Story` entries. Pick one at random when the Future is revealed.
- Avoid repeats: remember the last story index shown for each Future in `localStorage` (wrapped in try/catch) and don't pick it again next time if the Future has more than one story.
- Show the title, then the tagline, then the story's paragraphs (as in v3).

## 5. See what you chose

### Timeline focus

- The player's timeline now **starts at Now**. Show only the **3 most recent history events** above the Now marker, fading out upward with a gradient (`mask-image: linear-gradient(to bottom, transparent, black)` over those entries). Older history isn't shown here.
- Below Now, the player's own future fills the space: their 4 cards and any Events, alternating left and right, ending in the Future card at 2070, which is visually the biggest and brightest item.

### Values

- Each Value has a colour in story.md (`**Color:**`). Use it for the Value's **pill**, its **bar**, and the expanded panel's accent.
- The Value name sits in a **small pill**: rounded, with a tinted background in the Value's colour at about 20% opacity, the text in the full colour, and small caps or a small font size.
- **Hover:** hovering anywhere within a Value's row (its full vertical band, including pill, bar and end labels) highlights the whole row with a soft background band and a subtle lift, so it's obvious the row expands. Use `cursor: pointer` on the whole row.
- **Click anywhere in the row** (pill, words, bar, labels) to expand or collapse its detail panel. Keep the v3 panel contents (left means, right means, why it matters, where you landed).
- The bars keep the v3 shape: square at the centre line, rounded at the outer tip.

## 6. Cards

- Card art is **9:16**. From v4, the image generator will return plain rectangles, so **all corner rounding is done in CSS**: corner radius = **1/32 of the card's width**.
- Implementation: make each card a size container (`container-type: inline-size`) and give the face element `border-radius: calc(100cqw / 32); overflow: hidden;`, with images using `width: 100%; height: 100%; object-fit: cover;`. Apply this to card backs, fronts, Event cards, Future cards, the deck stack and timeline thumbnails, so every card at every size uses the same rule.
- **Replace both placeholder images** with the attached versions (exactly 1080 × 1920, with square-cornered edges trimmed so the CSS rounding is clean): `assets/cards/card-back.png` and `assets/cards/card-front-placeholder.png`.

## 7. Sound (fixes)

- **Card flip:** replace it with a **soft swoosh**. Use filtered noise (brown or pink, not white) through a bandpass filter whose frequency sweeps about 400 → 1600 → 700 Hz, with a gain envelope of about 120 ms attack and 300 ms release, peaking around 0.04. **Time it to the visual flip:** start it about 30% into the flip animation so its loudest point lands on the flip's midpoint, when the card is edge-on. Scale the timing for the slower Future flip.
- **Click:** the current pure beep sounds like an error. Replace it with a soft, warm **"tok"**: a sine that drops quickly from about 520 Hz to 360 Hz over 60 ms, plus a very short low-passed noise tick (under 15 ms), 3 ms attack, about 90 ms decay, peak gain about 0.03. For **confirming a Choice**, play a gentle two-note rise instead (a fifth, like A4 → E5, 80 ms apart, very quiet).
- **Ambient music:** give it movement.
  - **Chord progression:** cycle slowly through a progression, for example Am(add9) → Fmaj7 → Cmaj7 → Em7, changing every 14–18 s with about 4 s crossfades. Each chord tone is a pair of slightly detuned soft oscillators (sine plus triangle), panned gently left and right.
  - **Filter:** a slow low-pass filter LFO (about 0.04 Hz) for breathing.
  - **Bell notes:** sparse, soft notes picked at random from A minor pentatonic every 5–12 s, with a long reverb tail and random pan, so the music never sounds frozen.
  - Keep the master level low (about 0.06), fade in over 4 s after Begin, and dip under the Future reveal.
- If real audio files exist in `assets/audio/`, they still override the generated sounds (as in v3).

## 8. Particles

- Increase to about **220 on desktop** and **110 on phones**.
- Give some depth: two layers, with a far layer of smaller, dimmer, slower particles and a near layer that's slightly larger and reacts more to the cursor.
- Keep the gentle cursor push-away, pausing when the tab is hidden, and `prefers-reduced-motion` support.

## 9. Image generation plan (v4+, don't build now)

So the structure is ready later:

- Each card's image prompt will be its `**Image description:**` text, then a blank line, then the full `# IMAGE STYLE GUIDE` text, word for word.
- Images will be generated **ahead of time** by an offline script (`tools/generate-images.js`, v4), never in players' browsers. The API key must never ship in the front end.
- Output size will be 9:16 (for example 1080 × 1920), saved as `assets/cards/generated/<id>.png`. The script will write that path into the card's `**Image:**` field in story.md, and the game will use it automatically. No image editing is needed, because the CSS does the corner rounding.
- Cards: 30 Scenarios + 5 Events + 9 Futures = 44 images, plus the deck back.

For now, just make sure the parser reads `**Image:**` and `**Image description:**`, and that `IMAGE STYLE GUIDE` is parsed and available (e.g. `story.imageStyle`).

## 10. Writing guidance (updated, also for future edits)

**Clarity beats style.** Every card should make sense to someone who has never thought about AI:
- Open with who, where and what happened, like the first lines of a news story.
- Explain any idea a general reader might not know (an open model, a data centre) in plain words, the first time it appears.
- No vague openers that assume context ("Some countries didn't wait…").
- No references the reader has to decode (like "1945" without saying what happened then).
- If a reader might ask "but how could that happen?", answer it in the text.
- Each lead-in must make the jump from the previous card to the next one obvious.
